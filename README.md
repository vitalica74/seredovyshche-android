# Середовище Android — експериментальна збірка 0.1

Це **вихідний Android-проєкт**, а не готовий APK. Він містить інтерфейс «Середовище v0.1.3» і Android WebView-оболонку. APK автоматично збирається через GitHub Actions.

## Покроково: тільки телефон Android

### Крок 0. Резервна копія
1. У Chrome відкрий старе «Середовище» на `http://localhost:8000/?v=013`.
2. Для **кожного важливого проєкту** натисни **Експорт ZIP** і збережи файл у телефоні.
3. Не очищай дані Chrome і не видаляй стару папку з Termux.

### Крок 1. Створи окремий репозиторій GitHub
1. Відкрий `https://github.com/new` у Chrome (за потреби ввімкни «Версія для ПК»).
2. Назва репозиторію: `seredovyshche-android`.
3. Обери **Private** (можна Public, якщо хочеш відкритий код).
4. Натисни **Create repository**. Не додавай README або .gitignore автоматично.

### Крок 2. Розпакуй архів у Termux
Цей ZIP потрібно розпакувати у `/storage/emulated/0/Documents/Seredovyshche-Android/` (або іншу папку). У Termux, якщо ще не дозволено доступ до файлів:

```sh
termux-setup-storage
pkg install git -y
cd /storage/emulated/0/Documents/Seredovyshche-Android
ls -la
```

Після `ls` мають бути `settings.gradle`, `build.gradle`, `app`, `.github`, `README.md`.

### Крок 3. Надішли проєкт на GitHub
Виконай у Termux, **замінивши USERNAME своїм GitHub-логіном**:

```sh
cd /storage/emulated/0/Documents/Seredovyshche-Android
git init
git branch -M main
git add .
git commit -m "First Android shell"
git remote add origin https://github.com/USERNAME/seredovyshche-android.git
git push -u origin main
```

Якщо Git просить вказати ім'я та email, виконай `git config --global user.name "Ім'я"` і `git config --global user.email "email@example.com"`, тоді повтори commit/push. GitHub **не приймає пароль акаунта** для HTTPS git push: потрібен personal access token або налаштований SSH-ключ. Не надсилай токен у чат.

Якщо простіше, можна завантажити файли через GitHub вебінтерфейс, але **при цьому необхідно зберегти приховану папку `.github/workflows`**.

### Крок 4. Запусти збірку
1. Відкрий репозиторій у браузері.
2. Перейди до вкладки **Actions**.
3. Відкрий процес **Зібрати Android APK**.
4. Натисни **Run workflow** → **Run workflow** (або дочекайся автоматичного запуску після push).
5. Дочекайся зеленого статусу. Перший запуск може тривати кілька хвилин.

### Крок 5. Завантаж і встанови APK
1. Відкрий успішний запуск workflow.
2. Внизу сторінки знайди **Artifacts** → `seredovyshche-debug-apk`.
3. Завантаж ZIP-артефакт, розпакуй його: всередині `app-debug.apk`.
4. Натисни APK у файловому менеджері Android, дозволь установлення з цього джерела за запитом системи.
5. Відкрий застосунок **Середовище**.

**Увага:** debug APK підписується тестовим ключем збірки, який може змінюватися між запусками. Наступна збірка може не встановитися поверх попередньої без видалення застосунку, а видалення стирає локальні проєкти APK. **Перед будь-яким перевстановленням експортуй усі важливі проєкти.** Для нормальних оновлень пізніше зробимо стабільний release-підпис.

### Крок 6. Перенеси проєкти
1. У новому застосунку натисни **Імпорт ZIP**.
2. Обери раніше експортований ZIP.
3. Перевір файли, запусти проєкт і знову експортуй його для тесту.

## Що працює і що поки обмежено
- Не потрібні Chrome, Termux-сервер, мережа для запуску встановленого APK.
- Вбудовані HTML/CSS/JS файли, локальне сховище WebView, ZIP-імпорт через Android picker.
- ZIP/JSON-експорт через системний Android діалог збереження (WebMessageListener, тільки головний фрейм довіреного origin).
- Це **експеримент**: збірка GitHub Actions та робота на конкретному телефоні ще не перевірені на реальному пристрої.
- Поки немає окремого файлового сховища кожної мініпрограми, повного API дозволів, стабільного релізного підпису й мігратора браузерних даних.
- Проєкти всередині WebView не отримують довільного доступу до Android. Попередній перегляд ізольовано через sandbox iframe, однак для запуску недовірених чужих програм потрібен додатковий аудит безпеки.

## Якщо виникла помилка
- Червоний хрестик в Actions → відкрий збірку → `Build debug APK` → скопіюй **текст помилки** (без токенів).
- Не видно Actions → перевір, чи папка `.github/workflows/build-apk.yml` потрапила в репозиторій.
- Не видно APK → артефакт доступний тільки після успішного завершення workflow.
- Після встановлення білий екран → повідом версію Android і надішли скриншот; не очищай дані застосунку, якщо там є проєкти.

## Зміни наступних версій
Працюй у `app/src/main/assets/web/` для HTML/CSS/JS і в `app/src/main/java/` для Android. Для кожної зміни: `git add . && git commit -m "..." && git push` → Actions → новий APK. Поки немає стабільного підпису, **обов'язково роби резервні ZIP перед перевстановленням**.
